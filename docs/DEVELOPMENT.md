# Codex からの開発

接続先は `gas-project.json` の **Drop the Pin test**。GAS、データ用スプレッドシート、プロジェクトフォルダ、メディアフォルダを別々に記録しています。IDは認証情報ではありません。編集キー・編集URL・OAuthトークンはGitに保存しません。

## このPCでのコマンド

Node.js 24.14以降を推奨します。通常の環境では `npm`、このPCのPowerShellではリポジトリ内の `.\npm.cmd` を使います。npmとclaspはdevDependenciesでバージョンを固定しています。

```powershell
.\npm.cmd run gas:setup
.\npm.cmd run gas:doctor
.\npm.cmd run gas:links
.\npm.cmd run gas:status
```

新規チェックアウトでは、まずnpmを含むNode.jsを導入して `npm ci` を実行してください。上記 `npm.cmd` は依存インストール後に利用できます。Google認証がない環境では `node node_modules/@google/clasp/build/src/index.js login` を実行し、[Apps Script API設定](https://script.google.com/home/usersettings)を確認します。認証情報をリポジトリにコピーしないでください。

`gas:setup` は古い `.clasp.json` を `.codex-remote/previous-config-*` に退避して指定先へ接続します。リモートコードには触れません。各GASコマンドはscriptIdとrootDirを照合します。Windowsの信頼済み証明書を使う `NODE_USE_SYSTEM_CA=1` をGAS子プロセスだけに設定し、TLS検証は維持します。

## ローカル画面と自動テスト

```powershell
.\npm.cmd run dev
.\npm.cmd run validate
```

`dev` は既存のブラウザテスト用ハーネスを http://127.0.0.1:4173 で起動します。入口のリンクから編集テンプレート、共有テンプレート、音声編集・取込・再生を確認できます。Google呼び出しと地図をスタブにした**部品確認用**です。実データの保存・実地図・アプリ全体の初期化は実GASで確認します。HTML変更後はサーバーを再起動してください（Nodeのwatchが監視するのは主にJSモジュールです）。

Playwright未導入のPCは `node node_modules/@playwright/test/cli.js install chromium` を実行してください。自動テストは4173番を専用で使用するため、`dev` と同時利用する場合は先に `$env:DTP_BROWSER_PORT='4174'` を設定してdevを起動し、別ターミナルでその変数を外してテストします。

## GASへ反映する流れ

```powershell
.\npm.cmd run gas:snapshot
# 出力されたsnapshotのCode.js / index.html / shared.htmlをローカルと比較
git diff --no-index -- .codex-remote/snapshot-XXXX/Code.js Code.js
# 差分の確認後、実際に出力されたパスを指定
.\npm.cmd run gas:push -- --reviewed .codex-remote/snapshot-XXXX
```

`snapshot` は現行GASをGit対象外の新しいディレクトリへ取得します。作業ツリーで直接 `clasp pull` を実行するとローカル編集を上書きするので、このコマンドを使ってください。

`gas:push` はvendor・Node・ブラウザテストを実行し、リモートを再取得してレビュー時点から変化していないことを確認します。想定外のリモートファイルがある場合も停止します。3つのアプリソースだけをステージングへコピーし、**現在のGASのマニフェスト（タイムゾーン、権限、公開設定）を維持**してHEADを更新、再取得して一致を確認します。バックアップは残ります。Google APIには条件付き更新がないため、最終確認からpushまでの間はGASエディタでの同時編集を避けてください。

通常の `clasp push` はこれらの検査を通らず、リポジトリの `appsscript.json` の公開設定も反映するため、このテスト環境では `gas:push` を使います。`.claspignore` は実行に必要な4ファイルだけを許可します。

## 実アプリの初回起動

1. スプシをブラウザで開き「設定」→「初期設定」を実行します。GASエディタからの `setupSheet` はスプシを開いていないと `SpreadsheetApp.getUi()` エラーになる場合があります。初回のGoogle権限付与は所有者が内容を確認して行います。
2. スプシの初期設定完了ダイアログを閉じ、`config` の `IMAGE_DRIVE_URL` に `gas:links` のMedia URLを設定します。Project URLとは別のフォルダです。
3. GASの「デプロイ」→「デプロイをテスト」でウェブアプリを選択し、開発用 `/dev` URLを開きます。新しい公開デプロイが必要な場合は、まずアクセス範囲を**自分のみ**にして作成します。匿名公開は別途判断します。
4. 編集モードは `config` の `EDIT_KEY` と既存の編集URL機能を使います。`/dev?mode=edit&editKey=…` でHEADを検証できます。URL・キーをログやコミットへ貼り付けないでください。
5. `/dev` は最新の保存済みコードを実行しますが、Google側のプロジェクト編集権限が必要です。通常の `/exec` は固定バージョンなので、HEADをpushしただけでは更新されません。リリース時だけ「デプロイを管理」から対象を更新します。

スプシを使う操作は実データを変更します。テスト用ピンの追加・編集・削除、写真や音声の保存はテスト対象を限定してください。写真保存時には既存アプリが生成したメディアをリンク共有にする仕様があります。

2026-09-09に初期設定、メディアフォルダ設定、所有者のみのバージョン1デプロイを実施しました。`gas-project.json` に実際に取得した `/dev` と `/exec` を記録しています。その後、データ用スプシは非公開となっています。`config` に編集キーがあるため、アプリのアクセスを一般公開へ広げる際もスプシの共有範囲を維持してください。

テストGASのHEADはv2.2.0相当のアプリソースと同期・読み戻し照合済みです。固定バージョン1の `/exec` は初期v2.1.1のままで、開発には `/dev` を使います。写真9件とGPX1件が登録済みで、音声付きピンは未登録です。画面末尾にテンプレート条件タグが文字として出る問題は、後述の追加修正で解消しました。

2026-09-09の優先修正では、日時セルのタイムゾーン付き読取、編集・複製・タグ一括編集の文字列保護、ピン編集保存の二重送信・キャンセル・古い応答への対策を実装しました。シートの列や既存データを移行する必要はありません。実 `/dev` で9件の撮影日時の再表示と、編集フォームの日時復元・キャンセルを確認しています。実写真の内容を変更する保存は行わず、保存の往復・通信失敗・遅延中の操作はローカル回帰テストで検証しました。速度改善は対象外です。

## Codexへの引き継ぎ

### 起動・描画性能（2026-09-10）

`initializeApp` は設定取得、ピン／ルート取得、GPX取得を同時に開始します。GAS呼び出しは従来と同じ4種類です。編集可能になる条件は全取得の完了後のままとし、取得の順番が変わっても途中状態で編集しない構成です。メディア保存先の準備と音声vendorのバックグラウンド取得は初期データ完了後です。サーバーAPI・認可・シート構造は変更していません。

PCのピン領域に読み込み表示と、ピン取得失敗時の再試行（ページ再読み込み）を追加しました。スマホは既存の読み込み・再試行表示を維持します。ピンとルートの同時失敗でも、ルートのエラーを表示してからピンの失敗を処理します。

編集／共有画面のマーカー追加はmarkerclusterの `addLayers` で一括処理します。300ピンの合成データを使うローカルChromeの単回比較では、編集画面77.7ms→26.4ms、共有画面76.3ms→25.4msでした。これはGAS通信や写真取得を含まない描画処理の観測値で、実利用の起動短縮率を示すものではありません。回帰テストは時間の閾値ではなく、一括追加・ピン件数・既存操作と、初期要求がすべて応答前に開始されること、待機中の編集禁止、失敗経路を検証します。

参照: [GASの非同期通信](https://developers.google.com/apps-script/guides/html/communication)、[markerclusterの一括追加](https://github.com/Leaflet/Leaflet.markercluster#bulk-adding-and-removing-markers)。

検証はNode 1,578件・ブラウザ53件が成功。テストGASへ反映・読み戻し照合後、実 `/dev` で起動中の案内、完了時の案内消去、ピン9件・GPX1件、写真吹き出し、地図切り替えを確認しました。固定版 `/exec` は更新していません。GASや外部画像配信の待ち時間には変動があるため、実環境の起動短縮率は今回の単回確認から断定していません。

### 地図・写真表示の開発

共通の地図切り替え・クラスタ・写真吹き出しは `src/map-experience.js` と `src/map-experience.css` にあります。変更後に `node scripts/sync-map-experience.js` を実行すると、固定バージョンのmarkerclusterと共に `index.html` / `shared.html` へ同梱されます。生成領域を直接編集しないでください。`validate` は同梱内容とライセンスの同期も検査します。新しいGASファイルやスプレッドシートの列は不要です。

地図一覧は同モジュールの `backgrounds` で管理し、標準の選択肢は「通常地図」「陰影起伏図」の2つです。陰影起伏図は国土地理院へHTTPSで直接接続し、世界版を `underlays` に定義して日本の詳細図の下敷きにします。世界版だけの選択肢はありません。白地図とその専用描画処理・world-atlas/topojson-client依存・同梱データは削除しました。ライブラリのライセンスは `vendor/*-LICENSE.txt`、地図の出典は各レイヤーのattributionで確認できます。

2026-09-10: 比較後の方針に合わせ、日本の陰影起伏図の表示名を「陰影起伏図」に統一しました。世界版（`earthhillshade`、z0～8）と日本の詳細図（`hillshademap`、z2～16）の重ね表示、既存の注意書きは維持します。仕様・出典は[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)で確認。国内レイヤーへの要求は日本周辺の範囲に限定し、範囲外や低ズームでも中心・縮尺を変えません。国内タイルの全取得失敗では直前の背景を維持して再試行を表示します。一部の欠損タイルでは世界版が見える構成です。

地図選択は両画面の上部バー内 `#map-toolbar` にある「地図」ボタンから開き、外側のクリック・Escapeで閉じます。縮尺はLeafletの右下（出典表示の上）です。スマホでは下部パネルを避けて右下の表示位置を調整します。初期の通常地図とピンのまとめ方は維持しています。

この整理はNode 1,578件・ブラウザ49件で検証済みです。編集／共有、375px／1280pxで上部バーの収まりと縮尺の位置、日本国外の広域・拡大表示、国内タイルの失敗からの復帰、中心とズームの維持、日本の最大ズームでの2種類のタイルの重ね表示を確認しました。

同日の実 `/dev` でも、2つの選択肢、元の注意書き、追加地図の案内、世界版・日本版の画像取得、登録済み写真の吹き出しとGPXとの重ね表示を確認しました。GAS HEADはpush後の読み戻し照合済みです。固定バージョン1・公開範囲・シート構成・既存データは変更していません。

`/map-edit` と `/map-shared` のローカルハーネスは実Leafletと実markerclusterを使い、GASと外部画像の通信をテスト側で置き換えます。既存の `/production-edit` / `/production-shared` は部品検証用の地図スタブを維持します。

2026-09-09の追加修正では、ルート一覧・GPXの取得失敗を表示して再読み込みを可能にし、既に取得したデータを通信失敗時に捨てないようにしました。GPXの一部破損は警告件数を表示し、読めたデータを表示します。Drive共有エラーの原因断定を解消し、音声エディタのテンプレート条件は `HtmlTemplate.getRawContent()` から得た生のHTML上で処理します。起動診断は編集URLの `debugStartup=1` をサーバーから渡します。ルートキャッシュ容量対策・起動速度改善は次の段階です。

2026-09-09には実 `/dev` で登録済み写真の吹き出し・info・拡大、ピンのクラスタ展開、当時の世界白地図、地理院タイルの取得、条件タグの非表示、起動診断を確認しました。共有画面は実Leafletを使うローカルブラウザテストで検証し、共有権限を追加する操作はしていません。実データへの故障注入はせず、通信失敗・部分破損・遅延応答・再試行は自動テストで検証します。

2026-09-09の最終検証はNode 1,580件・ブラウザ39件が成功。編集キーなしの実 `/dev` でも編集用コードを除外した状態でピン9件・GPX1件が表示されることを確認しました。白地図専用の境界テストは、その機能の削除と共に廃止しています。

### 地図の個人カスタマイズ

追加地図の案内は編集・閲覧画面および共有画面の「使い方」末尾に配置します。普段の地図切り替えメニューには置きません。

標準の地図に加えたい場合は、自分のアプリの `src/map-experience.js` の `backgrounds` にタイルの設定を追加します。独自の `id`、表示名の `name`、HTTPSのタイルURL（`{z}/{x}/{y}`）、出典の `attribution`、提供されるズーム範囲の `minZoom` / `maxNativeZoom` を指定します。単独の世界地図なら `fallback` は不要です。現在の `fallback` は日本の範囲へ詳細図を重ねるための構成なので、他地域の重ね表示には範囲の変更も必要です。

提供元の利用条件・料金・必要な登録を各自で確認してください。アプリ内に地図URLやAPIキーを登録する画面はありません。追加後は上記の同梱生成、`validate`、GASの差分レビューと反映を行い、自分の `/dev` で表示を確認します。

最初にこの文書と `gas-project.json` を確認し、`gas:doctor` と `gas:snapshot` で接続先と差分を調べます。アプリの変更→`validate`→差分レビュー→`gas:push`→開発用URLで確認、の順に進めます。設定・認可チェックの迂回や、編集トークン免除は追加しません。

Gitは専用ブランチへローカルコミットします。この環境ではGitHubへ接続・プッシュしません。

例外: v2.2.0リリースは2026-09-10のユーザー指示により、`codex/response-performance` の改修を `master` へスカッシュ統合し、GitHubへ `master` とタグ `v2.2.0` をプッシュしてリリースノートを公開します。GitHubリリースとGASの固定バージョン更新は別の操作です。
