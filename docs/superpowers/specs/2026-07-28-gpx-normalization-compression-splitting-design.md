# GPX重複除去・圧縮・行程分割 設計

## 目的

YAMAPやウェアラブル端末から書き出したGPXを、重複点や高頻度な記録、宿泊を伴う長時間行程が含まれていても安全に取り込めるようにする。保存済みトラックの1件20,000 point上限は維持し、必要な場合は入力を複数トラックへ分割する。

## 基本方針

GPXの処理順は次のとおりとする。

1. GPX 1.0／1.1として全pointを検証・正規化する。
2. 証明可能な完全重複pointだけを除去する。
3. 長時間の記録中断を行程境界として分割する。
4. 各行程が20,000 pointを超える場合だけ、最大5秒間隔まで必要最小限に圧縮する。
5. 5秒間隔でも20,000 pointを超える行程は、連続する複数トラックへ追加分割する。
6. 複数トラックになった場合は、`元の名前(1/N)`、`元の名前(2/N)`のように命名する。

元GPXは変更しない。保存対象だけを正規化し、除去数、圧縮内容、分割理由を取込プレビューへ表示する。

## 入力上限と保存上限

- GPXファイル上限は既存どおり5MBとする。
- XML安全検証、GPX version／namespace、座標、標高、時刻、segment数の既存契約を維持する。
- GPX解析時のsource point安全上限を100,000 pointとする。
- 保存される各トラックは既存どおり最大200 segment、20,000 pointとする。
- 一度のGPX取込で生成できるトラック数に20件の上限を設ける。
- 保存済みトラック全体の既存上限100件を維持する。

source point上限は、重複除去や圧縮より前の件数へ適用する。上限超過時は部分取込せず、安全な固定メッセージで拒否する。

## 完全重複の除去

同じ元segment内で、次の全項目が正規化後に一致するpointを完全重複とみなす。

- 時刻
- 緯度
- 経度
- 標高（未設定を含む）

最初のpointだけを残し、離れた位置に再出現した重複も除去する。時刻のないpointは同一観測と断定できないため除去しない。別segmentのpointは、値が一致してもsegment境界を維持するため除去しない。

不正pointを重複として読み飛ばしてはならない。全pointを既存契約で検証してから重複判定する。

## 宿泊相当の行程分割

元segment境界は常に維持する。同一segment内で、連続する時刻付きpointの時刻差が4時間以上ある場合、その間を新しい行程の境界とする。

- 日付が変わっただけでは分割しない。
- 夜行登山のように時刻が連続している場合は分割しない。
- 時刻のないpointを挟む箇所は自動分割しない。
- 4時間未満の休憩は行程分割しない。

分割後も元のpoint順とsegment順を維持する。行程境界をまたぐ線を描画せず、写真時刻照合でも境界をまたいだ位置補間を行わない。

## 自動圧縮

各行程を個別に評価し、重複除去後のpoint数が20,000以下なら圧縮しない。

20,000を超える場合、時刻付きpointには1秒、2秒、3秒、4秒、5秒の候補を順に適用し、20,000以下になる最小間隔を採用する。各segmentの先頭と末尾は必ず残し、segmentごとに間隔判定をリセットする。

時刻のないpoint、または時刻だけでは20,000以下にできない混在データは、元の順序を維持した均等抽出を補助的に使用する。この場合も全segmentの先頭と末尾を優先して残す。均等抽出で5秒を超える時刻間隔を意図的に作らず、20,000以下にできない場合はpointを追加削除せず次の追加分割へ進む。

距離、標高範囲、開始・終了時刻、boundsは保存対象pointから再計算する。圧縮前の集計値を保存済みトラックへ混入させない。

## 20,000 pointごとの追加分割

最大5秒の圧縮後も1行程が20,000 pointを超える場合、point順を維持して複数の保存トラックへ分割する。

- 既存segment境界を優先して切る。
- segment内で切る必要がある場合は、各トラックが20,000 point以下になる境界を選ぶ。
- 追加分割でpointを捨てない。
- 分割境界のpointを重複保存しない。
- 各トラックのsegment indexは0から振り直す。

分割境界では別トラックになるため、Leaflet上では境界をまたぐ線を描画しない。最大5秒相当の1区間が欠ける可能性はプレビューで明示する。

## 名前と編集項目

出力が1トラックなら元の名前を維持する。複数なら文書順に`元の名前(1/N)`形式のsuffixを付ける。100文字上限を超える場合はsuffixを残して元の名前側を切り詰める。

複数トラックは次を共有する。

- description
- color
- visible
- lineStyle
- lineWidth
- sourceType
- sourceName

取込プレビューでは共通の名前を編集し、保存名のsuffixを再生成する。保存後は既存のトラック編集機能で各名前を個別に変更できる。

## 取込プレビュー

単一トラックと複数トラックを同じプレビューで扱う。複数時は生成予定一覧を文書順で表示し、各項目に次を示す。

- 保存名
- 行程の開始・終了時刻
- segment数
- 保存point数

全体の処理結果として次を表示する。

- source point数
- 完全重複除去数
- 検出した4時間以上の中断数
- 採用した圧縮間隔と圧縮除去数
- 生成トラック数

処理を行わなかった項目は警告として表示しない。複数トラックになる場合は、保存前にその件数と名前を確認できるようにする。

## 複数トラック保存と再試行

既存の`saveTrackBundle`を各トラックへ直列に呼び出す。Sheet書込み競合を避けるため並列保存しない。

保存開始時に全trackId、revisionId、payloadを確定し、再試行でも変更しない。途中で失敗した場合、再試行は同じpayload列を先頭から送る。保存済み項目は既存のrevision冪等性により`deduplicated: true`で確認され、未保存項目から処理を継続できる。

クライアントは保存前に現在のトラック数と生成件数を検査する。サーバー側の100件上限判定は各保存で引き続き強制する。部分成功後は「保存済み件数／全件数」を表示し、取込を未保存状態へ戻さない。全件成功後にだけ取込完了とする。

## Coreと既存API

`GpxTrackInterchangeCore`へbatch draft APIを追加する。単一出力時の既存`parse`、`buildDraft`、`updateDraft`、`toSavePayload`契約は維持し、既存GPXの回帰を防ぐ。

batch draftは生成順のdraft配列と、プレビュー用の安全な件数・処理結果だけを返す。XML本文、座標、ファイルパス、例外stackをwarningや画面メッセージへ含めない。

サーバーのtracks／track_segmentsスキーマ、各トラックpayload、共有payload形式は変更しない。

## エラー処理

- 5MB、source point 100,000、生成20トラック、保存済み100トラックの各上限を区別する。
- 分割・圧縮後に空トラックまたは空segmentを生成しない。
- ID生成はGPX全体の解析・分割・圧縮が成功した後に行う。
- 解析失敗時は1件も保存しない。
- 保存の部分成功は件数を表示し、同一payloadで再試行可能にする。
- 生のGPX内容や内部例外を画面へ表示しない。

## テスト設計

### Core

- 実ファイルと同型の完全重複が20,000 point上限判定前に除去される。
- 同一segment内の離れた完全重複を除去する。
- 時刻なし、標高差、座標差、時刻差、別segmentのpointは除去しない。
- 不正pointが重複候補でも既存の安全なエラーで拒否する。
- 日付変更だけでは分割せず、4時間未満と4時間以上の境界を区別する。
- 夜間も連続する軌跡を分割しない。
- 既存segmentと長時間中断の双方を維持する。
- 1～5秒のうち20,000以下になる最小間隔を選ぶ。
- 20,000以下の行程は圧縮しない。
- segment先頭・末尾、順序、時刻、標高を維持する。
- 時刻なしデータの均等抽出と、5秒を超える削除をしないfallbackを確認する。
- 5秒後も超過する行程を追加分割し、全pointを順序どおり1回だけ保存する。
- 100,000 source point、20生成トラック、100文字名の境界を確認する。
- summaryとstatsが保存対象pointから再計算される。

### UI workflow

- 単一出力の既存プレビューと保存が変わらない。
- 複数出力の一覧、suffix、共通編集、集計を表示する。
- payloadを直列保存し、成功順にstateへ反映する。
- 途中失敗後の再試行でIDとpayloadが変わらず、保存済み応答を重複追加しない。
- 保存前の100トラック上限、保存中の二重送信、閉じる操作を安全に扱う。
- warningとエラーへGPX本文や座標を表示しない。

### 回帰

- GPX 1.0／1.1、trk／rte、namespace、XML安全検証、metadata優先順位を維持する。
- GeoJSON取込、保存済みトラック編集、共有表示を変更しない。
- サーバーは20,000 pointを超える単一payloadを引き続き拒否する。

## ドキュメント

READMEのGPX制約を、単純な「20,000 pointまで」から次へ更新する。

- 5MB、source point最大100,000
- 完全重複の自動除去
- 必要時のみ最大5秒間隔まで自動圧縮
- 4時間以上の中断による複数トラック化
- 各保存トラック20,000 point、1回最大20トラック

## 非対象

- 元GPXファイルの書換えや別名保存
- 近似座標や近似時刻を使った曖昧な重複除去
- 日付だけを使った日程分割
- 10秒以上の自動圧縮
- ルートグループ用の新しい永続化形式
- 日程ごとの色や線種の自動変更
- tracks／track_segmentsシートのmigration
